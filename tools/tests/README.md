# 測試

在**專案根目錄**執行：

```bash
node tools/tests/run-all.js          # 全部（約 30 秒）
node tools/tests/run-all.js --fast   # 略過兩支耗時稽核（約 5 秒）
node tools/tests/render-test.js      # 單獨跑某一支
```

## 為什麼這些測試放在版控裡

原本寫在 `/tmp`，暫存目錄被清空後二十幾支測試一次全部消失。
測試是驗證正確性的唯一憑據，放在會被清空的地方等於沒有測試。

## 每一支在守什麼

| 檔案 | 守的東西 |
|---|---|
| `render-test.js` | 246 個實驗在兩種主題下都能建置、重繪、停止 |
| `theme-audit.js` | 不該出現「刺眼白塊」或「黑洞」——注入真實 CSS 變數值後掃描全站填色 |
| `meaning-audit.js` | 每一根滑桿都必須讓畫面產生看得見的變化 |
| `ink-test.js` | 墨色層的顏色語意：主題衍生色放行、寫死顏色搶救 |
| `contrast-test.js` | 兩種主題的文字與介面對比達 WCAG AA |
| `layout-test.js` | 同列面板等高、疊圖層對齊、孤兒 class 掃描 |
| `physics-test.js` | 核心實驗對照封閉解（單擺、彈簧、落體、電路、氣體、能量守恆） |
| `relation-test.js` | 142 個模板實驗的關係圖有資訊、亮點落在曲線上 |
| `insight-test.js` | 自動關係摘要符合已知物理，且探測不污染滑桿 |
| `metrology-test.js` | 量具讀數規則（游標不估讀、測微器必估讀、半毫米陷阱） |
| `a11y-test.js` | 畫布的文字替代、觸控目標尺寸 |
| `perf-test.js` | 首次載入（壓縮後）與延遲載入沒有被抵銷 |
| `build-consistency.js` | 全站版本號一致、SW 快取清單與實際檔案相符 |
| `graph-ink-test.js` | 圖表裡的曲線與陰影，在兩種主題下都與底板有足夠對比 |
| `control-response-test.js` | **暫停狀態下**每一根滑桿都要造成看得見的改變 |

`meaning-audit` 與 `control-response-test` 看起來重疊，其實守的是不同狀態：
前者在動畫跑著的時候量，後者在「剛打開、還沒按播放」的時候量。
實驗進場預設是暫停的，所以後者才是學生真正遇到的第一個畫面——
41 個實驗把重繪整個放在動畫迴圈裡，在前者眼中一切正常，在後者眼中全部是死的。

## 這些測試驗不到什麼

全部在 Node 的 DOM 替身裡跑，量的是**繪圖指令**與**程式邏輯**，
不是**畫面看起來對不對**。指令不同不代表學生看得懂，
也不代表版面沒有重疊、顏色沒有打架、文字沒有被裁掉。

本專案至今每一個嚴重的畫面問題，都是使用者截圖才發現的：
深色主題的白方塊、淺色主題的黑底板、左右不等高、滑桿拉了沒反應。
**發佈前請實際打開瀏覽器看過。**

## 測試自己出過的錯（避免重蹈）

| 症狀 | 原因 |
|---|---|
| 稽核回報 0 筆問題 | 變數注入沒生效，`col()` 一路回傳 fallback |
| 淺色主題回報兩萬多筆假黑洞 | 用 `indexOf("@media print")` 切範圍，把淺色變數整段砍掉 |
| 把青綠、橘色算成白塊 | 只看亮度；刺眼的是「灰白」，必須同時看彩度 |
| 波形實驗被判成靜態插圖 | 只 hook `PL.draw.*`，漏掉原生 `ctx.lineTo()` |
| 兩支力箭頭互換方向卻判定沒變 | 雜湊用加總，對「對調」是盲的 |
| 相位 0° 與 360° 被判成沒作用 | 只比 min 與 max，週期性參數兩端是同一個狀態 |
| 導線粗細變化偵測不到 | 只錄座標，沒錄 `lineWidth` |
| 首次載入回報超標 | 量原始位元組，但實際傳輸是 gzip |
| 532 支滑桿「全部沒反應」 | dispatch 寫在錄影區間外，同步畫的那一格根本沒被錄到 |
| 41 個正常實驗被判成壞的 | harness 的事件不會冒泡，掛在容器上的監聽器等於不存在 |
| 28 支正常滑桿被判成沒反應 | harness 的 `querySelectorAll` 不支援逗號選擇器，回傳 0 筆 |
| 陰影對比「引擎算 1.50、測試算 1.20」 | 測試的相對亮度漏了 gamma 反轉，先去改了引擎才發現錯在稽核 |
| 半衰期滑桿被判成沒反應 | 錄影只記文字座標不記文字內容，座標軸縮放後兩張圖雜湊相同 |

上面五筆全部發生在同一天、同一支新稽核上。共通點是：
**稽核宣稱找到問題時，第一件事是先懷疑稽核。**
「找到 532 個缺陷」比「找到 0 個」更可疑——真實的缺陷不會那麼整齊。

**一個回報 0 筆問題的稽核，和一個根本沒在測的稽核，輸出長得一模一樣。**
每支稽核開跑前都必須先證明自己有在測。
